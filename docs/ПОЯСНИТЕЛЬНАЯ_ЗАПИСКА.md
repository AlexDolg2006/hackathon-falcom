# Аннотация

«Питомец Финни» — мобильное игровое приложение для формирования базовой финансовой грамотности у детей 7–11 лет. Ребёнок заботится о виртуальном коте, получает игровые монеты, планирует их распределение на обязательные расходы, желаемое и накопления и наблюдает последствия решений. Приложение написано на Godot Engine 4.7, работает офлайн, не собирает персональные данные и не запрашивает разрешений Android.

# 2. Назначение и образовательные результаты

Целевая аудитория — дети 7–11 лет, которые только знакомятся с карманными деньгами. Взрослый поддерживает ребёнка, но не принимает решения за него.

Образовательные результаты выбраны из раздела 1 ТЗ (Единая рамка компетенций):

| № | Компетенция | Механика приложения |
|---|---|---|
| 1 | Расходы не превышают доходов | Покупка возможна только в пределах бюджета своей категории |
| 2 | Обязательное и желаемое | Две категории товаров и направлений плана |
| 3 | Простые покупки при ограниченном бюджете | Блокировка покупки при нехватке с объяснением |
| 4 | Краткосрочная цель, регулярные накопления | Четыре цели, доля накоплений в плане, срок достижения |
| 5 | Оценка своих решений | Сравнение плана и факта, итоги периода, объяснение после каждого задания |
| 6 | Использование приложения вместе со взрослым | Раздел для взрослого с обзором прогресса |

Почему механика питомца работает: обязательные расходы напрямую влияют на сытость и чистоту кота, желаемые — на настроение, поэтому ребёнок видит смысл разделения трат. Ошибок-«наказаний» нет: кот не болеет и не исчезает, показатели восстанавливаются покупками и уходом.

## Debug

`godot --headless --export-debug "Android" build/game.apk`. CI `android-build.yml` делает то же по push в `develop` и `main`.

## Релизный подписанный APK

1. Создать ключ вне репозитория: `keytool -genkeypair -v -keystore ~/finni-release.keystore -alias finni -keyalg RSA -keysize 2048 -validity 10000`.
2. Задать `GODOT_ANDROID_KEYSTORE_RELEASE_PATH`, `GODOT_ANDROID_KEYSTORE_RELEASE_USER`, `GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD`.
3. Собрать: `godot --headless --export-release "Android" build/finni-release.apk`.
4. Проверить: `apksigner verify --verbose build/finni-release.apk`, `aapt dump permissions build/finni-release.apk`.

CI-вариант: секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEY_ALIAS`, `ANDROID_KEYSTORE_PASSWORD`, затем тег `v1.0.0`; workflow `android-release.yml` прикрепляет APK к релизу GitHub.

# 4. Архитектура

| Слой | Файлы | Ответственность |
|---|---|---|
| Контент | `data/shop_items.json`, `tasks.json`, `education_tips.json` | товары, задания, цели, справочник |
| Логика и состояние | `scripts/autoload/GameData.gd` | экономика, питомец, период, цели, задания, сохранение |
| Оболочка | `scripts/ui/Main.gd` | верхняя панель, нижняя навигация, меню «Ещё» |
| Общие элементы UI | `scripts/ui/UIUtils.gd` | окна сообщений и подтверждения, стиль кнопок |
| Экраны | Onboarding, Home, Shop, Wash, MiniGame, Budget, Goals, Tasks, History, Adult | отображение и ввод |
| Графика | `PetCanvas.gd` | процедурная отрисовка кота |

Поток данных: экран вызывает метод `GameData` → `GameData` меняет состояние, вызывает `save_game()` и сигнал `state_changed` → экраны перерисовываются. Сигнал `toast` показывает короткие сообщения о начислениях. Экраны не хранят игровое состояние. Навигация: нижняя панель «Дом / Покупки / Игра / Бюджет», меню «Ещё» — накопления, задания, прогресс, раздел для взрослого.

Обновление учебного контента: правка JSON в `res://data/` без изменения логики.

# 5. Структуры данных

## Профиль (`user://save_game.json`)

| Группа | Поля |
|---|---|
| Профиль | `first_launch`, `pet_created`, `is_demo_profile` |
| Питомец | `pet_name`, `body_color_index` (0–2), `pattern_index` (0–2), `equipped_hat`, `equipped_wash`, `pet_stage` (0–2), `growth_points`, `mood`, `hunger`, `hygiene` (0–100) |
| Деньги | `wallet`, `mandatory_budget`, `optional_budget`, `savings` |
| План | `plan_pct_mandatory`, `plan_pct_optional`, `plan_pct_savings`, `plan_mandatory`, `plan_optional`, `plan_savings`, `fact_mandatory`, `fact_optional` |
| Период | `period_active`, `plan_required`, `period_number`, `day_in_period` |
| Календарь | `global_day_counter`, `last_login_day_key`, `last_minigame_day_key` |
| Цель | `current_goal_id` |
| Коллекции | `inventory` {id: количество}, `completed_tasks` [id], `history` [итоги периодов], `purchase_log` [{name, price, category}] |

Элемент `history`: `period_number`, `plan_*`, `fact_*`, `interest`, `good_period`, `grew`, `new_stage`, `end_mood`, `end_hunger`, `end_hygiene`.

## Контент

- **Товар:** `id`, `name`, `price`, `category` (`mandatory` / `optional`), `desc`, `hunger`, `mood`, `slot` (`hat` или `wash`), для средств купания `wash_power`.
- **Задание:** `id`, `topic`, `topic_name`, `title`, `scenario`, `type` (`choice` / `input`), `reward`, `explanation`. Для `choice`: `options` [{`id`, `text`, `correct`, `feedback`}]. Для `input`: `total_hint`, `min_mandatory`.
- **Цель:** `id`, `name`, `cost`. **Термин:** `term`, `definition`.

Ограничения: полученная награда всегда 10 монет (поле `reward` только отображается); новый тип задания требует правок `TasksPanel.gd`; шапки рисуются по id (`hat_cap`, `hat_crown`, `hat_bow`).

# 6. Формулы и правила экономики

| Правило | Значение |
|---|---|
| Старт | 60 монет в кошельке |
| Бонус за вход | +10, один раз за игровой день |
| Доход за день | +25 автоматически при завершении игрового дня |
| Мини-игра | 20 с, 1 монета = +1, одна попытка за игровой день |
| Задание | +10 за первое выполнение |
| План | проценты трёх направлений в сумме 100, обязательное > 0, по умолчанию 50/30/20 |
| Подтверждение плана | весь кошелёк делится: обязательное и желаемое — `floor(сумма × %)`, накопления — остаток |
| Доход в период | делится теми же процентами между бюджетами и накоплениями |
| Период | 5 игровых дней; после закрытия нужен новый план |
| Ежедневное снижение | сытость −18; настроение −6, ещё −8 при сытости < 30; чистота −10, ещё −5 при сытости < 30 |
| Бонус на накопления | `savings += round(savings × 0.05)` при закрытии периода |
| Остатки | бюджеты обязательного и желаемого возвращаются в кошелёк |
| Срок цели | `ceil((стоимость − накопления) / средний взнос)`, средний взнос — среднее `plan_savings` по `history` |
| Удачный период | на конец периода сытость ≥ 40, настроение ≥ 50, потрачено на обязательное > 0 |
| Стадия | 2 очка → 1, 4 очка → 2 |
| Лицо питомца | настроение ≥ 70 весёлый, ≥ 35 обычный, иначе грустный |
| Чистота | купание повышает чистоту и немного настроение; названия: Чистый ≥ 70, Немного грязный ≥ 40, Грязный ≥ 20, Очень грязный |

Пример 60 монет при плане 50/30/20: обязательное 30, желаемое 18, накопления 12.

Пример без покупок за 5 дней: сытость 62, 44, 26, 8, 0; настроение 74, 68, 54, 40, 26; период не «удачный», рост не начисляется.

# 7. Карта образовательного контента

| Тема | Задание | Навык | Сценарий | Правильная логика | Объяснение ребёнку |
|---|---|---|---|---|---|
| Планирование бюджета | budget_1 «Первая монетка» (choice) | приоритет обязательного | 40 монет на 5 дней: еда и мыло или корона | сначала обязательное, остаток на желаемое | «Сначала обеспечь обязательное, а уже потом трать на желаемое» |
| Планирование бюджета | budget_2 «Раздели монеты» (input) | распределение по трём направлениям | 60 монет, обязательного не менее 20 | сумма ≤ 60 и обязательное ≥ 20 | при малом обязательном не хватит на еду |
| Формирование сбережений | savings_1 «Коробочка для монет» (choice) | регулярность накоплений | копим на велосипед | откладывать понемногу каждый период | регулярные небольшие взносы работают лучше случайных остатков |
| Формирование сбережений | savings_2 «Проценты на накопления» (choice) | нетронутые накопления растут | что будет с бонусом при раннем снятии | бонус уменьшится или не начислится | накопления, которые не трогают, растут |
| Платежи и покупки | purchase_1 «Не хватает монет» (choice) | решение при нехватке | корона 45 монет, на желаемое отложено 30 | подождать или выбрать дешевле, не уходить в минус | нехватка — повод скорректировать план, не ошибка |
| Платежи и покупки | purchase_2 «Обязательное или желаемое?» (choice) | различение категорий | мыло и бантик | мыло — обязательное, бантик — желаемое | мыло нужно для ухода, бантик просто радует |

После любого ответа ребёнок видит объяснение. В заданиях `choice` засчитывается любой выбранный вариант (безопасная ошибка), правильность отражена в тексте обратной связи. В задании `input` неверный план не засчитывается, можно повторить.

# 8. UX/UI и доступность

Решения: короткие фразы; крупные заголовки; основные действия — заметные кнопки-«пилюли»; подтверждение перед покупкой, планом, сбросом и удалением; окна подстраиваются под ширину экрана; цветовые состояния дополнены текстом.

| Требование ТЗ 3.6 | Состояние |
|---|---|
| Цель нажатия ≥ 48 dp | Кнопки 42–64 px в окне 1080×1920. На телефоне шириной 360 dp 1 px ≈ 1/3 dp, поэтому реальный размер меньше; нужна проверка на устройстве и увеличение размеров |
| Текст ≥ 16 sp, системное увеличение | Шрифты 15–30 px; в `GameData.gd` есть масштаб интерфейса `ui_scale` 0.8–2.0, но он не сохраняется между запусками |
| Цвет — не единственный признак | Да, состояния дублируются текстом и значками |
| Звуки и анимации | Звуков нет; переключателя анимаций нет |
| Подтверждение опасных действий | Да |
| Единообразная навигация | Нижняя панель и меню «Ещё» на всех экранах |

# 9. Разрешения Android, данные, удаление

- Разрешения: в `export_presets.cfg` все разрешения выключены, включая INTERNET. Проверка релизного APK: `aapt dump permissions`.
- Данные: только `save_game.json` на устройстве (раздел 5). Реальных имён, телефонов, e-mail, платёжных данных нет, данные не покидают устройство.
- Удаление: «Ещё ▾ → Раздел для взрослого» (пример на сложение) → сброс или удаление профиля с подтверждением. Файл перезаписывается пустым профилем; полностью данные исчезают при удалении приложения.

# 10. Инструкция для экспертной комиссии

1. Установить APK на Android 8.0+.
2. Пройти знакомство и создать питомца.
3. Демонстрационный режим: «Ещё ▾ → Раздел для взрослого» → решить пример → кнопка сброса профиля к тестовому.
4. «Завершить текущий день» на вкладке «Бюджет» проходит день за днём без ожидания; пять нажатий закрывают период.
5. Все задания доступны сразу («Ещё ▾ → Финансовые задания»).
