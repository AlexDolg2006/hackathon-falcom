# Питомец Финни — hackathon-falcon

Игровой сервис для формирования базовых финансовых навыков у детей 7–11 лет.
Godot 4.7, мобильная сборка под Android. Виртуальный кот: кормёжка, купание,
настроение/сытость, магазин (еда/мыло/шапки), ежедневная мини-игра "лови монетки",
план личного бюджета на 5 игровых дней (обязательное / желаемое / накопления
с фиксированным процентом), финансовые задания, накопления на цель, история и
раздел для взрослого.

## Стек
- Godot Engine 4.7 (GDScript), рендер mobile.
- Экспорт: Android (Gradle build, см. `export_presets.cfg`).
- Хранение данных: JSON-файл в `user://save_game.json` (сохранение прогресса) +
  контентные JSON в `res://data/` (магазин, задания, цели, справочник —
  редактируются без изменения логики, см. п. 2.5.14 ТЗ).
- Графика питомца рисуется процедурно (`PetCanvas.gd`, `_draw()`), внешние
  ассеты не требуются — так проще расширять/менять расцветки.

## Структура репозитория
```
project.godot            # настройки проекта, автозагрузка GameData
main_dashboard.tscn       # корневая сцена (см. run/main_scene), содержит только Main.gd
scripts/
  autoload/GameData.gd    # состояние игры: экономика, питомец, планы, цели, задания, save/load
  ui/Main.gd               # шелл приложения: верхняя панель, нижняя навигация, переключение экранов
  ui/OnboardingPanel.gd    # первый запуск: знакомство + создание питомца (гостевой режим)
  ui/HomePanel.gd          # главный экран: питомец, статы, доход дня, быстрые переходы
  ui/PetCanvas.gd          # процедурная отрисовка кота (цвет, узор, стадия, шапка, настроение)
  ui/ShopPanel.gd          # магазин: еда/мыло (обязательное), шапки/игрушки (желаемое)
  ui/MiniGamePanel.gd      # мини-игра "лови монетки", доступна 1 раз в игровой день
  ui/BudgetPanel.gd        # план бюджета на 5 дней + завершение дня/периода
  ui/GoalsPanel.gd         # накопления, выбор цели, прогресс, снятие с подтверждением
  ui/TasksPanel.gd         # финансовые задания (мини-сценарии) по 3 темам
  ui/HistoryPanel.gd       # прогресс, итоги периода, завершённые задания, справочник терминов
  ui/AdultPanel.gd         # раздел для взрослого (барьер — арифметический пример)
data/
  shop_items.json          # 9 товаров, 2 категории (обязательное/желаемое)
  tasks.json               # 6 заданий, 3 темы (бюджет, накопления, покупки)
  education_tips.json      # каталог целей (goals) + справочник терминов (glossary)
android-build.yml          # готовый workflow для GitHub Actions (экспорт debug APK)
```

## Быстрый запуск (редактор)
1. Установить Godot 4.7 (stable).
2. Открыть папку проекта в Godot (`project.godot`).
3. Нажать Play (F5) — стартует `main_dashboard.tscn`.

## Сборка APK
### Локально
1. Godot → Editor → Manage Export Templates → скачать шаблоны для 4.7.
2. Project → Export → Android → Export Project → debug APK.
3. Либо через CLI: `godot --headless --export-debug "Android" build/game.apk`.

### Через CI (уже настроено)
См. `.github/workflows/android-build.yml` (переместите `android-build.yml` из
корня в `.github/workflows/` при подключении к GitHub). Workflow сам скачивает
Godot 4.7.2, шаблоны экспорта, Android SDK/NDK, создаёт debug keystore и
собирает `build/android/game.apk`, публикуя его как артефакт сборки.

## Демонстрационный режим и тестовый профиль
Раздел «Ещё → Раздел для взрослого» (барьер — решить пример) →
кнопка **«Демонстрационный режим: сбросить к тестовому профилю»**. Она:
- сбрасывает локальный профиль к исходному состоянию (тестовый профиль);
- игровые периоды проходятся кнопкой «Завершить текущий день» без ожидания
  реального времени — так весь обязательный сценарий (Приложение А ТЗ)
  можно пройти подряд за пару минут.

## Формулы и правила экономики
- Доход дня: +25 монет по кнопке «Забрать доход дня», один раз за игровой день.
- Игровой период = 5 дней. До начала периода все доступные ("непристроенные")
  монеты кошелька распределяются в плане на 3 направления: обязательное,
  желаемое, накопления. Покупки списываются именно из бюджета своей категории.
- Проценты на накопления: по завершении периода `savings += round(savings * 0.05)`
  (константа `SAVINGS_RATE` в `GameData.gd`) — фиксированный процент.
- Неизрасходованные остатки бюджета обязательного/желаемого по итогам периода
  возвращаются в кошелёк для нового плана (ничего не сгорает).
- Рост питомца: если за период сытость ≥ 40, настроение ≥ 50 и обязательное
  направление было хоть немного потрачено — период считается «удачным»,
  начисляется очко роста. 2 очка → стадия 1 («Подросший кот»), 4 очка → стадия 2
  («Взрослый кот-мудрец»). Никаких дебафов/«смерти» — только грустная мордочка
  при низком настроении/сытости.
- Мини-игра: 20 секунд, монеты падают, корзина двигается пальцем/мышью —
  сколько поймано, столько монет зачисляется в кошелёк. Доступна 1 раз в
  игровой день (аналогично доходу дня, независимый счётчик).

## Известные ограничения и план развития
- Графика питомца процедурная (векторные фигуры), а не рисованные спрайты —
  осознанный выбор для хакатона без художника; легко заменить на `Sprite2D`
  с реальными ассетами, интерфейс `PetCanvas.gd` инкапсулирует отрисовку.
- Нет облачной синхронизации/аккаунта — по границам задачи это не требуется
  (обязательный сценарий работает офлайн и без сбора персональных данных).
- Раздел для родителя ограничен обзором прогресса и сбросом/удалением профиля
  без отдельного веб-кабинета (это вне обязательного минимума, п. 2.7).
- Автоматизированных unit-тестов пока нет; ключевая логика бюджета/покупок
  находится в `GameData.gd` и легко покрывается тестами через GUT или
  GdUnit4 — рекомендуется добавить при развитии проекта.
- Мини-игра использует упрощённое управление (перетаскивание по полю) —
  для реального релиза стоит добавить аккуратную физику и звук.

## Разрешения Android
Профиль экспорта (`export_presets.cfg`) не запрашивает ни одного опасного
разрешения — обязательный сценарий не использует камеру, микрофон,
геолокацию, контакты и т.д. (см. п. 3.1.4, 3.5 ТЗ).

## Удаление и сброс данных
Взрослый может сбросить или полностью удалить локальный профиль из раздела
«Ещё → Раздел для взрослого» без обращения к разработчику (см. п. 3.5 ТЗ).
